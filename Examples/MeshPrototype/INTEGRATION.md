# Персонажи и окружение в одной SKScene

Дополнительная `IntegrationScene` не заменяет `DemoScene`. Переключатель AppKit над SKView и клавиша Tab выбирают одну из двух сохранённых сцен. После возврата сохраняются playhead, пауза и настройки; `didMove(to:)` сбрасывает только отметку времени предыдущего кадра. `--integration` сразу открывает новую сцену, обычный запуск — прежнее демо. Benchmark и прежний `--verify` работают без панели переключения.

## Содержимое

Два Goblins движутся по встречным замкнутым траекториям: проходят перед и за забором и деревом, меняются местами по глубине. Окружение создано обычными `SKSpriteNode` и `SKShapeNode`: дорожка, деревья, забор, полупрозрачный передний план, движущиеся светлячки. Сцена использует стандартное alpha blending. Это проверка отрисовки и слоёв, не физическая симуляция столкновений.

Камера автоматически меняет положение, масштаб и небольшой угол поворота. HUD прикреплён к камере. C отключает автоматическое движение; +/− изменяют масштаб; A меняет alpha персонажей. Space, стрелки, W, R и 0 управляют паузой/шагом, wireframe, отражением и сбросом. На время отсутствия на экране сцена не продвигает своё время.

## Порядок отрисовки

[SpriteKit складывает zPosition родителей и детей](https://developer.apple.com/documentation/spritekit/sknode/about_node_property_propagation), поэтому одного контейнера SKNode недостаточно для изоляции частей персонажа.

В интеграционной сцене `Goblin.confineDrawOrder(to: 1)` размещает все слоты, группы треугольников и wireframe внутри локального диапазона `[0, 1)`. `TriangleMeshNode.setTriangleDepthSpan(_:)` ограничивает диапазон внутренних треугольников, сохраняя их порядок. Геометрия и обновления позы не меняют этот диапазон.

Персонажи, деревья и забор сортируются по координате Y точки контакта с землёй; при равном Y используется стабильный порядок создания. Каждый объект получает базовый z с шагом 2. Обычные дочерние элементы дерева/забора также лежат в `[0, 1)`. Окружение не может оказаться между слотами персонажа. Объект переднего плана перекрывает только те пиксели персонажа, которые покрывает его собственная геометрия/alpha.

Исходная сцена и performance benchmark сохраняют прежний порядок слоёв; ограничение диапазонов включено только для дополнительной сцены. Это пока API прототипа, не изменение production runtime Spine.

## Проверки

```sh
swift test --package-path Examples/MeshPrototype
swift run -c release --package-path Examples/MeshPrototype MeshPrototype --verify-integration Examples/MeshPrototype/output/integration
```

Интеграционная проверка вызывает action переключателя и передаёт Tab в обработчик view, проверяет сохранение обоих экземпляров сцен и состояния. Это программная проверка маршрута управления, не автоматический клик/нажатие через macOS Accessibility.

Восемь снимков сравнивают текущий `.triangle` renderer с группой 2 против `.mesh` renderer с группой 1. Эталон использует интерполированные UV прямоугольника, поэтому независим от framebuffer-матрицы. Обе сцены включают окружение, движение/поворот/масштаб камеры, отражение, alpha и несколько размеров view. Матрицы кандидата готовятся тем же `prepareRasterCoordinates(scene:view:)`, что в живой сцене. Для чтения пикселей используется SKRenderer с target, соответствующим размеру view и backing scale.

Проверяются обе стороны дерева и порядок относительно забора, а также полный внутренний диапазон z каждого персонажа. Дополнительный unit test проверяет сохранение порядка и диапазона треугольников при смене winding для групп 1/2/4.

Для этой проверки преобразований камеры установлен строгий допуск 3/255 на канал по всему кадру: интерполяция цвета между эталонными mesh bounds и экранными координатами может различаться на несколько младших разрядов. Число каналов с отличием выше прежних 2/255 записывается отдельно. Допуски существующих тестов renderer не изменялись.

Результат на M1 Max / macOS 26.6: 10 unit tests и все 8 сравнений прошли. Максимальное отличие — 3/255; каналов с отличием выше 2/255 — 1, выше 3/255 — 0. Проверены передний/задний проход у дерева и сохранение обеих сцен. [Сохранённый отчёт](Verification/2026-10-03-integration.json). Прежний `--verify` также прошёл: базовые сценарии и 128 + 16 + 160 сравнений без новых расхождений.

## Границы проверки

Использованы macOS, обычная SKScene/SKCameraNode, sprites/shapes и alpha blending. Снимки получены GPU-интеграционным тестом, не захватом рабочего стола. `SKEffectNode`, `SKCropNode`, освещение SKLightNode, normal maps и специальные blend modes этой сценой не проверяются. Автоматический контракт для промежуточных framebuffer по-прежнему не реализован. Работа с окружением не добавляет отсутствующие возможности Spine runtime.
